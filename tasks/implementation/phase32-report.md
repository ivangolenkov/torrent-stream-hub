# Phase 32: Файловое Логирование И REST API (Отчёт)

## 1. Что Сделано

- `internal/logging/files.go`: потокобезопасный вывод в консоль и ежедневные файлы `hub-YYYY-MM-DD.log`, append после рестарта, календарная очистка при запуске, ротации и раз в час. Ошибки диска не отключают консоль; диагностика и повторные попытки ограничены по частоте. Каталог и файлы открываются через `os.Root`, посторонние файлы и symlink не выбираются для очистки.
- `internal/logging/reader.go`: независимые дескрипторы с зафиксированными размерами, потоковое чтение и обратный блочный поиск начала tail. Открытые файлы защищены от retention до закрытия снимка; mutex writer не удерживается во время сетевой передачи. Длинные строки не требуют загрузки целиком в память.
- `internal/logging/adapters.go`, `logging.go`: общий вывод для стандартного `log` и `slog`, сохранение уровней, маскирование секретов, включая quoted/grouped атрибуты. Библиотечный DEBUG tracing не включается.
- `internal/config/config.go`: настройки `HUB_LOG_DIR` / `--log-dir`, `HUB_LOG_RETENTION_DAYS` / `--log-retention-days`, проверка корректности и приоритет CLI над env. Значение `0` не теряется при применении defaults.
- `internal/delivery/http/api/log_handlers.go`: `GET /api/v1/logs`, фильтры `date` либо `from`/`to`, общий `tail=1..100000`, строгая валидация параметров и безопасные ошибки. Успешный ответ — plain text; все ответы endpoint имеют `Cache-Control: no-store`.
- `internal/delivery/http/router.go`: передача зависимости чтения, сохранение CORS `*`, access logs без query/headers/ANSI после завершения ответа. Обработанные panic сохраняют stack trace.
- `internal/engine/client_config.go`: подключён штатный `Slogger` anacrolix. Проверено, что при незаданном старом `Logger` fork перенаправляет его в этот handler; изменений fork не потребовалось.
- `cmd/hub/main.go`: файловый вывод инициализируется до БД/engine. Ошибки старта возвращаются через `run()` и логируются до закрытия файлов вместо выхода через `log.Fatal`, пропускающего defer. Обработана ошибка HTTP listener и принудительное закрытие сервера при timeout shutdown.
- `internal/usecase/sync_worker.go`: добавлен совместимый `StartContext`, чтобы остановить worker перед закрытием engine, БД и логов.
- Добавлены тесты writer/reader/adapters, конфигурации, REST API, HTTP logging/panic, startup failure и остановки sync worker.
- Обновлены `README.md`, `docker-compose.yml`; в отчёте Phase 31 отмечена подтверждённая пользователем ручная приёмка Lampa.

## 2. Зафиксированное Поведение

- По умолчанию файлы находятся в `logs` рядом с БД; в стандартном Docker deployment — `/config/logs` внутри постоянного volume.
- Хранятся текущий день и три предыдущих календарных дня. Значение `0` оставляет только текущий день; верхняя граница настройки — 36500 дней.
- Используется локальный часовой пояс процесса. Очистка опирается на дату имени, не на `mtime` или 72 часа; активный writer и открытые snapshots не удаляются.
- Без даты API выбирает сегодня; диапазон включительный. Пропущенные дни внутри диапазона пропускаются. Нет подходящих файлов — `404`; существующий пустой файл — пустой `200`.
- Tail относится ко всей выборке и выдаётся в хронологическом порядке. Незавершённая последняя строка учитывается; финальный newline не создаёт дополнительную строку. Между непустыми файлами вставляется newline, если предыдущий файл его не содержит.
- Ответ ограничен размерами файлов на момент открытия и не следует за новыми записями. Это не транзакционный snapshot всего каталога и не `tail -f`.
- Management API фактически не применяет Basic Auth: одни настройки `HUB_AUTH_ENABLED` не защищают endpoint. Это явно описано в README; доступ следует ограничивать доверенной сетью/reverse proxy.
- Прямой вывод в stdout/stderr и аварийные Go runtime dumps не перехватываются. Суточная ротация не ограничивает размер активного файла.

## 3. Проверки И Результаты

Успешно выполнено на macOS arm64:

```bash
go test -count=1 ./...
go test -race -count=1 ./internal/logging ./internal/config ./internal/delivery/http/... ./internal/usecase ./internal/engine ./cmd/hub
go vet ./...
go build -o bin/hub ./cmd/hub
git diff --check
```

Race detector не обнаружил гонок. При линковке race-тестов с torrent dependency macOS linker выдаёт предупреждения `malformed LC_DYSYMTAB`; команды завершаются успешно, тесты проходят.

Проверены ротация и append, права новых файлов, календарная граница retention с DST, фоновая очистка без записей, ошибки удаления/открытия/ENOSPC, восстановление writer, сохранность посторонних файлов и symlink, конкурентные запись/чтение/очистка, cancellation, повторное закрытие, фиксированный размер снимка и удержание файлов до завершения чтения.

Проверены маскирование стандартных/библиотечных сообщений, групповые и quoted секреты, отсутствие query-секретов/ANSI в access logs, stack trace panic, отсутствие access log текущего download в его теле, ошибки API без раскрытия внутренних путей и без дописывания JSON после начала ответа.

В тесте большой истории tail последней строки читает не больше 32769 байт. Бенчмарк одной строки длиной 4 МиБ:

```text
BenchmarkTailLongLine-16   934   1228659 ns/op   32774 B/op   2 allocs/op
```

Дополнительно выполнен smoke test собранного сервера с временной БД/каталогами: `GET /api/v1/logs?tail=3` вернул `200`, `text/plain; charset=utf-8`, `no-store` и не больше трёх строк. Проверены дневной файл, запись HTTP access log и успешный выход по SIGTERM. Тестовые каталоги удалены.

## 5. Уточнения И Отходы От Плана

- Существенных архитектурных отклонений нет. Дополнительно ограничен срок хранения сверху (36500 дней), чтобы исключить переполнение/неразумные значения настройки.
- Для согласованного tail файлов с незавершённой последней строкой введён разделяющий newline при объединении. Он одинаково применяется в полной выдаче и tail и описан в README.
- Минимальное расширение lifecycle sync worker потребовалось, чтобы прекращать фоновые producer logs до закрытия ресурсов. Старый `Start()` сохранён для совместимости.
- Новая аутентификация не реализована, как и предусмотрено границами фазы; фактическое отсутствие защиты существующих management routes не скрывается.
- Полноценный ручной прогон на Windows/Linux не выполнялся; runtime smoke test и автоматические проверки выполнены на macOS. POSIX permission assertions и symlink tests учитывают ограничения Windows.
