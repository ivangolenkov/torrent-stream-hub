## Реализованный Блок A06

- `internal/logging/async.go`: production wrapper над rooted Files с отдельными file/console workers. На каждый sink не более 512 ожидающих записей/2 MiB, плюс одна in-flight запись; предел сообщения 64 KiB. Drop-newest, независимые budgets, копирование caller buffers, redaction до очереди и UTF-8 truncation с маркером.
- Producer не ждёт sink I/O. Queue mutex не удерживается на Write/cleanup. Flush ожидает завершения попыток записи принятого префикса, а не fsync/durable delivery; stats различают завершённые попытки и ошибки возвращённые sink.
- Context-aware close закрывает admission до ожидания workers, не закрывает borrowed stdout. Default ожидание 2s. После timeout зависший worker сохраняет владение ресурсом и завершает drain/cleanup после возвращения syscall; новые workers не создаются. Late writes учитываются как dropped.
- `cmd/hub/main.go` подключён к AsyncFiles. `UseFiles` принимает writer interface; существующие standard/slog/HTTP adapters проходят через production async destination.
- `internal/logging/async_test.go`: blocked console/file-output independence, bounded flood, copy semantics, truncate/redact, short writes, concurrent stop/flush/enqueue, close timeout и cleanup после release.
- `internal/usecase/STATE.md`: реализованный ownership/identity/commit/coordinator contract; repository Lifecycle удалён, engine admission сужен до reservations/validation/effects.
- `internal/logging/rotation.go`, `files.go`, `reader.go`: размерные segments с фиксированным 12-digit номером, правильный legacy/segment порядок в full/tail и безопасный append после reopen. Бюджет считает все управляемые обычные файлы, включая oversized legacy и pinned snapshots. Непривязанные inactive segments удаляются от старых к новым; защищённые не обрезаются. Если budget занят защищённой историей, append pauses; quota retries не чаще раза в минуту либо после unpin. Backlog использует дату события, захваченную до enqueue, а не дату обработки worker.
- `StorageStats` считает filesystem errors (включая подавленные rate limit summaries), потерянные file records/bytes и quota pause независимо от sink lock. Queue stats содержат drop severity (неизвестные raw записи — unknown), rejected-after-close и close timeouts. Timeout не выдаётся за доказанную потерю in-flight записи: worker может завершить её позже.
- `GET /api/v1/logs/status` возвращает stats с `no-store` через общую CORS-схему. Handler не открывает log store и не ждёт filesystem lock; неподдерживаемый reader получает 503.
- Config: `HUB_LOG_MAX_FILE_BYTES`/`--log-max-file-bytes` (16 MiB), `HUB_LOG_MAX_TOTAL_BYTES`/`--log-max-total-bytes` (128 MiB); строгая проверка parse/overflow/positive/file>=64KiB/total>=file и CLI precedence. Production default level — info, явный debug поддержан. README и compose актуализированы.
- Добавлены `rotation_test.go`, `log_status_test.go`, config boundary tests, tests независимости blocked file от console/stats, severity/late writes. Проверены 16 segments с реальным reopen, tail order, pinned budget/recovery, backlog через полночь, сохранность oversized legacy и чужих файлов.

## Приёмка И Ограничения

- A06 реализован в согласованном объёме. Queue Errors считает ошибки sink attempt, Storage.Errors отдельно считает filesystem errors: их не следует складывать в число уникальных неуспешных записей. File loss может включать запись, часть bytes которой успела сохраниться перед ошибкой. Shutdown оставляет фиксированные workers владеть зависшим I/O до его завершения; финальная diagnostic summary также может быть dropped при закрытом/переполненном console sink.
- Старый Files остаётся синхронным внутренним file sink и используется существующими прямыми fixtures. Production получает его через AsyncFiles; неблокирующая гарантия относится к production wrapper, не к произвольному прямому Files.Write.
- A01: production writers разделены; typed durable faults, commit/apply/retry/reopen и bounded cross-source validation реализованы. REST/SSE/command receipts и Vue используют server epoch/decimal sequence, включая пустые списки; timestamps не являются authority.
- A02: independent run/operation/slot/completion/fault policy и общий executor; activity ортогональна. A04: все Lifecycle consumers перенесены на общий hash/root coordinator; engine preparation/registration/Drop/Resume/restore/metadata/absence I/O вынесен за global admission с проверкой поколения/версий/reservations. Локальная сериализация конфликтующих операций одного record/root сохраняется намеренно.
- Проверка disk budget сканирует управляемый namespace перед append; её стоимость зависит от числа имеющихся segments, не является обещанием O(1) или NAS throughput. Queue и defaults ограничивают retained memory и рост логов, не прерывают произвольный filesystem syscall. Внешний конкурентный writer в каталоге логов не поддерживается. Уже oversized protected legacy history может превышать budget до освобождения pin; новые bytes не дописываются поверх занятого budget.
- Полная итоговая приёмка выполнена: root ×3, full race, targeted race ×5, vet/build, frontend **22 tests**/build и обязательные fork suites/race. NAS/Smart TV, физические ENOSPC/power-cut/readonly и иные platform runtimes не проверялись. Library/SQLite locks и непрерываемые syscalls не устранялись. Scope не включает auth, dependency upgrades, F09/F11/F12 или общий storage rewrite; прежний npm audit не объявляется исправленным.

## Финальная Реализация A04 И Publication Ordering

- `command_coordination.go`, `coordinator.go`, `torrent_uc.go`, `temporary.go`, `recheck.go`, `storage_migration.go`, `sync_worker.go`: единый application-owned registry для live/DB-only hash/root keys. Resolve/acquire/revalidate с максимум двумя попытками; active/waiting refs, ordered aliases и cancellation предотвращают два locks на один объект. Existing record ID захватывается до ожидания и проверяется после него: старый waiter не действует на повторно добавленную запись того же hash (отдельный deterministic test). SyncWorker принимает usecase, а не создаёт отдельный coordination domain. Все repository Lifecycle references/поле удалены.
- Add сначала парсит input вне locks, затем insert-only резервирует mapping/aliases, отпускает и заново получает полный resolved root-key set с повторной проверкой перед runtime/intent effects. `EnsureStorageMapping` не заменяет concurrent reservation, `SaveStorageAlias` условен по root. Shared-root команды сериализованы, но не по всему приложению. Initialization mutex охватывает только короткую DB initialization, не I/O или ожидание record locks.
- Temporary policy/lease maps имеют короткий data mutex. Release несёт record ID; old release не уменьшает новый counter. Cleanup TryLocks pass/candidate keys, перечитывает FIFO и limit/защиту под reservation; busy/protected head откладывается без destructive guessing. Add не ждёт чужого cleanup. Migration держит work ticket, отпускает command keys на hash/copy, сохраняет durable moving/manifest veto, проверяет record ID перед finalize и перечитывает desired intent перед restore. Keep-delete тоже запрещён при незавершённом migration manifest.
- Coordinator закрывается Engine context, отменяет waiting handles и присоединяет active commands без нужных им locks. HTTP actions/priorities/download/preload admission передают request context. Late commands после shutdown не создают нового intent; отдельно barrier проверяет shutdown ПОСЛЕ deletion commit: engine refusal оставляет durable mode/error и не выполняет unlink. Это уточнение прежнего stopped-engine теста, а не потеря recovery contract.
- `runtime_work.go`, `engine.go`, `restore.go`, `metainfo.go`, `missing_payload.go`, `stream.go`: generation/epoch/binding validation вокруг unlocked Resume/cache/probe/metadata/stat work. Registration резервирует unpublished pointer, Drop/closers — detaching namespace до завершения; same-namespace re-add конфликтует до retirement. Direct descriptors/Drop выполняются после unlock; owned tasks предотвращают resource close из-под работы. Unknown restore events отклоняются до raw Add/restore I/O. Library locks и их собственные задержки не обещаются устранёнными.
- Параллельная приёмка обнаружила настоящий SQLite deferred read→write `BUSY_SNAPSHOT`: successful-pin тест мог получить ошибку до commit. `write_tx.go` резервирует writer через BEGIN IMMEDIATE до command reads; read-only snapshots остаются deferred/WAL. Transactions содержат только DB work, busy timeout/pool PRAGMA сохранены. При неуспешном rollback соединение отбрасывается, а не возвращается с открытой transaction. Тест подтверждает чтение WAL snapshot до release uncommitted writer и отсутствие overwriting alias claims.
- `snapshot_clock.go`, `PublishedSnapshot`, REST/SSE handlers и CORS: random Engine epoch + decimal sequence, allocated BEFORE capture/JSON, paired latest-only data/version. REST array body совместим; header `X-Hub-Snapshot`, SSE `id:` работают и для `[]`. Command receipt retires более раннюю publication, даже если JSON задержан. `snapshotOrder.ts`, client/store: constant-size watermark вместо growing tombstone map, lossless compare, fresh REST handshake при новой SSE epoch, guards retired command/record ID и async request; закрытый EventSource не публикует callbacks.
- Новые проверки: `coordinator_integration_test.go` (blocked hash/copy/unlink A vs B Pause/lease, moving workflow conflict, cancelled waiter, old lease release/re-add, shutdown after commit); `detach_test.go`, `registration_reservation_test.go`, runtime work/slot preparation tests; `write_tx_test.go`; `snapshot_version_test.go`, `snapshot_publication_test.go`, `snapshot_clock_test.go`, Vue snapshotOrder/store tests с large sequences, пустыми списками, сменой процесса и delayed old-record acknowledgments. Старые regression/failure suites сохранены, а не исключены ради зелёного результата.

## A01/A02 — Activation, Terminal Events, Typed Faults И Activity

- `state_transition.go`, `engine.go`, `restore.go`: registration, Resume/full activation и Delete/Close переведены на общий dispatcher/executor; произвольный `setStateLocked` удалён. Close копирует ManagedTorrent pointers перед effects, не держит Engine.mu через overlay reconcile. Сначала quiesce, затем add-only safety persistence. ## A04 — Fenced Scheduler/Payload Preparation И Coordinator Primitive

- `ManagedTorrent` владеет policy epoch и attachment-local slot token; каждое новое grant выдаёт новый token. Pending preparation — pointer capability с epoch/runtime fence/slot token. Прежний `admitPayloadLocked` сохраняет caller-held/return-held контракт admissionMu, но копирует inputs и **отпускает его** на disk probe и metainfo persistence. После reacquire проверяет generation/current pointer/epoch/binding/slot/reservation до любого Allow/priority effect; stale result возвращает conflict. Параллельная preparation того же runtime получает conflict, не новый worker/retry queue.
- Scheduler больше не держит global admission на весь проход. Refresh storage completion и health probes вынесены наружу; health tickets coalesce один blocked syscall без ожидания остальных scheduler passes на нём. FIFO head и actual reservation count пересчитываются под admissionMu на каждом grant, а не из старого local activeCount. Pending preparation занимает capacity. Cleanup сверяет slot token и не освобождает replacement reservation после Pause/Resume. Неизменившийся selection observation не продвигает epoch, priority mutations продвигают.
- Owned work admission охватывает unlocked preparation/pass: Close закрывает admission/cancels, quiesces и joins без удержания admissionMu, не закрывая ресурсы из-под probe. Непрерываемость произвольного syscall остаётся явно указанным ограничением.
- `admission_preparation_test.go`: B Pause до release blocked A probe; stale probe после Pause и delete/re-add; concurrent scheduler до release reserved preparation; capacity и новый slot token после Pause/Resume против старого cleanup; Close join без admission lock. Тестовый fake использует atomic first-call election, не `sync.Once` вокруг blocked syscall (такой Once сам сериализовал бы probes B и подменял проверяемую независимость).
- `coordinator.go`/`coordinator_test.go`: application-owned keyed registry без repository ownership. Active/waiting references защищают lock identity, cancellation убирает waiter/ref, ordered/deduplicated canonical/alias sets предотвращают opposite-order deadlock, try-reservation позволяет будущему eviction не ждать второго unordered key. Repeated release/close безопасны, close отменяет waiters и joins owned handles без registry/record locks; registry пуст после завершения/cancellation. Это **primitive до переноса consumers**, не заявление об удалении Lifecycle. Не выполнены общий lease/namespace/eviction migration, прочие Resume/registration/Drop/unlink/copy critical sections и полная A04 acceptance matrix.

## Read Models — Bounded Cross-Source Validation

- `engine/read_stamp.go`: короткий capture/validate runtime pointer map, policy epoch, runtime binding, applied revision и apply-failure identity. Stamp включает отсутствие runtime и map membership; phase ABA или replacement не проходят проверку. Locks не удерживаются на SQLite/library reads.
- `usecase/consistent_read.go`: каждая попытка сравнивает два согласованных SQLite DTO snapshots вокруг immutable runtime capture и проверяет runtime stamp. Не более двух попыток; дальнейший churn — `ErrSnapshotConflict` (сохраняет errors.Is repository state conflict), а не guessed policy/пустой список. REST single/list и SSE используют один validated mapper. List/files HTTP возвращают 409; SyncWorker оставляет последнюю публикацию. JSON всё ещё вне Lifecycle.
- Durable comparison намеренно консервативен: повторно читает весь запрошенный DTO set, включая observations. Это дополнительная стоимость на NAS и возможные retry/conflict при частых изменениях; полноценный repository snapshot revision может оптимизировать это позже, но unbounded retries не введены. Library speed/peer/byte/activity остаются telemetry samples, не транзакцией с SQLite и не readiness authority.
- `consistent_read_test.go`: команда между источниками, runtime-only Pause/Resume ABA без DB write, delete/re-add с новым record ID, постоянно изменяющийся revision и реальная DB read failure. Existing async verification polling test теперь принимает bounded snapshot conflict как retryable read outcome в пределах прежнего deadline; ошибка не скрыта в production mapper.
- Publication epoch/sequence, пустой versioned list и Vue tombstone/delete-readd ordering всё ещё не реализованы. Existing browser timestamp barriers не объявляются заменой этому протоколу.
