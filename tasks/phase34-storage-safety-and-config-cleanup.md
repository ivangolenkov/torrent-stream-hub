# Фаза 34: Безопасный Доступ К Файлам И Очистка Конфигурации

## Статус И Зависимости

- Статус: запланировано; реализация только по отдельной команде пользователя.
- Начинать после проверки DoD и отчёта фазы 33.
- Основание: `tasks/draft/codebase-audit-2026-10-21.md`, **F01, F02, F03, F04, F10**.
- Разбиение на фазы 34–36 согласовано с пользователем. Эта фаза защищает существующий layout, не ожидая его миграции в фазе 35.

## Цель И Границы

Исключить удаление/выдачу чужих файлов из-за угадывания путей, исправить настройки SQLite и меню действий. По решению пользователя не вводить авторизацию, а удалить её неработающие настройки.

Не входят: изоляция payload по infohash и hash-verification (фаза 35), восстановление приоритетов и DiskFull (фаза 36), остальные находки аудита. Минимальные изменения deletion lifecycle необходимы для безопасного повтора F01; полное устранение F17 и общий рефакторинг FSM отдельной целью не являются.

## Контракт Файловых Операций — F01/F02

### Единое Разрешение Путей

- Ввести общий механизм получения точного storage manifest из проверенных metadata и фактического layout. Разделить физический относительный путь, отображаемое имя и индекс файла.
- Переиспользовать существующие гарантии `internal/usecase/temporary_files.go` и root-based streaming, не создавать третью независимую политику.
- Нельзя выбирать путь по одному имени/размеру или пробовать оба варианта `file.Path` и `torrent.Name/file.Path`.
- Для старых записей без доказуемого layout запрещать файловую операцию с диагностируемой ошибкой. Неизвестный manifest не равен подтверждённому пустому manifest.
- Использовать `os.Root` для фактического открытия/удаления; лексической проверки или проверки перед обычным `os.Open` недостаточно. Проверять регулярность и размер по открытому descriptor, а не только по имени до открытия.
- Запретить traversal, абсолютные пути, выход через symlink, пересечение со служебными данными и неоднозначное владение зарегистрированными payload. Учесть `.part`, case/unicode aliases и hardlink aliases в пределах проверяемого владения.
- `os.Root` не является защитой от любых действий локального пользователя с правом менять файловую систему. Границы защиты от hardlinks/внешней подмены явно описать; не заявлять криптографическую проверенность до фазы 35.

### Ручное И Автоматическое Удаление

- Общая операция файлового удаления для ручного Delete и FIFO-очистки; правила выбора кандидата остаются разными. Ручное удаление постоянного торрента разрешено, автоочистка постоянного запрещена.
- Удалять только подтверждённые payload и соответствующие `.part`, затем только пустые каталоги. Убрать `os.RemoveAll` fallback и удаление по предположительному имени.
- Проверять весь manifest и конфликты до первого unlink. Отсутствующий файл допускает идемпотентный повтор, но не отменяет проверку владения.
- Сохранять намерение и точный manifest до удаления файлов; незавершённое удаление не должно автоматически восстановить загрузку при рестарте. Допустимо переиспользовать/расширить механизм фазы 33.
- Согласовать с add/delete/cleanup/SyncWorker и приёмом передач. Для ручного удаления используемого торрента возвращать конфликт без частичного удаления; учитывать stream, direct stream, preload, download/ZIP и debounce. Не держать lifecycle lock во время передачи.
- `deleteFiles=false` сохраняет payload; изменение семантики TorrServer drop/rem/wipe вне необходимой защиты не входит.

### Download И ZIP

- Открывать single-file download и ZIP entries через общий root-based механизм; не передавать непроверенный абсолютный путь handler для повторного `os.Open`.
- Проверять manifest архива до отправки заголовков; каждое открытие entry остаётся root-contained. Имена внутри ZIP относительные, без traversal.
- Сохранить HEAD, Range, Content-Disposition, защиту активной передачи и закрытие descriptor при ошибке/отмене.
- Не выдавать `.part`, неподходящий тип файла, данные по неоднозначному/служебному пути. Сохранить существующие проверки готовности, не подменяя их совпадением размера.
- HTTP: отсутствующий торрент/файл — 404; конфликт использования/неподтверждённый layout — 409; ошибка хранилища/БД — 500. Использовать существующий формат ошибок; чувствительные абсолютные пути не раскрывать.

## Конфигурация И SQLite

### F03: Удаление Неработающей Авторизации

- Удалить `AuthEnabled`, `AuthUser`, `AuthPassword`, CLI `--auth-enabled`, `--auth-user`, `--auth-password` и чтение `HUB_AUTH_*`.
- Удалить эти настройки из README, Compose, актуальных примеров и соответствующих описаний в ТЗ; проверить Makefile и config-тесты.
- Старые CLI-флаги становятся неподдерживаемыми с обычной ошибкой парсинга; старые env не дают защиты и больше не читаются. Отразить это в заметке об обновлении.
- Сохранить краткое предупреждение: встроенной авторизации нет, API и логи доступны всем имеющим сетевой доступ; использовать доверенную LAN или защищённый reverse proxy. Не рекламировать несуществующие параметры.
- Исторические отчёты и исходный аудит не переписывать. Не удалять маскирование Authorization/секретов и tracker authentication: это другие механизмы.
- CORS `*` сохранить на всех endpoint.

### F04: Настройки Каждого SQLite Соединения

- Исправить DSN под `modernc.org/sqlite`: `_pragma` для `busy_timeout(5000)` и `foreign_keys(1)`, WAL для файловой БД. Корректно объединять существующие query-параметры, не добавлять второй `?` и не повреждать путь.
- Проверять фактический режим WAL; для специальных in-memory DSN явно определить исключение, поскольку WAL там недоступен.
- Пул остаётся явно ограниченным. При любой ошибке Ping/PRAGMA/миграции закрывать уже открытый `sql.DB`.
- Миграции существующей базы и транзакционность операций сохраняются; SQLite не заменять.

## Тестирование

- Удаление single/multi-file, final/part, пустой/неполный manifest; одноимённый посторонний файл и вложенный каталог не затронуты; никаких guessed-path fallback.
- Traversal, symlink в каждом компоненте, служебные пути, shared paths, доступные платформенные aliases; отказ безопаснее удаления при неоднозначности.
- Частичный unlink, отказ БД, рестарт и повтор; отсутствие возобновления незавершённого удаления. Конкурентные add/pin/delete/FIFO/SyncWorker и admission передач.
- Download/ZIP: точный файл, неверный размер/тип, symlink escape, ошибки открытия после preflight, HEAD/Range, отмена и закрытие ресурсов.
- SQLite: удерживать несколько соединений одновременно и проверять PRAGMA на каждом; новый connection после закрытия старого; FK violation/cascade, lock contention с bounded timeout, заполненная старая БД и DSN с параметрами.
- Config: удалённые флаги не распознаются, в help/актуальных примерах нет auth-настроек. CORS не изменён.
- Автоматизированный браузерный/component regression открытия меню после async boundary; desktop/mobile, повторный клик, удалённая строка, отсутствие console errors. При необходимости добавить минимальную тестовую инфраструктуру.
- Проверки: `go test ./...`, `go test -race ./internal/... ./cmd/...`, `go vet ./...`, `go build ./cmd/hub`, `npm run build` в `web/`, frontend regression-тесты, `git diff --check`.
